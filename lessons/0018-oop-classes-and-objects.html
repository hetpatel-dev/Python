Lesson 18: OOP — Classes & Objects

concept Object-Oriented Programming, Classes, Instances, Methods, Properties

Object-Oriented Programming (OOP) is a programming paradigm that organizes code around objects — bundles of data and behavior. Classes are the blueprints for creating objects. This lesson covers the official Python tutorial on classes, data model, and descriptor protocol.

Primary sources: Tutorial — Classes, Instance Objects, Method Objects, Class and Instance Variables, classmethod, staticmethod, property, __slots__, dataclasses, Descriptor HowTo Guide.

1. Introduction to Object-Oriented Programming

OOP is a programming paradigm that organizes code around objects rather than functions and logic. An object bundles data (attributes) and behavior (methods) into a single unit.

What is OOP?

  • Blueprints and houses: A class is like a blueprint; an instance is like a house built from that blueprint.
  • Encapsulation: Grouping related data and functions together.
  • Abstraction: Hiding complex implementation details behind simple interfaces.
  • Code reuse: Classes can be extended and composed to build complex systems.

Why Use Classes?

  • Organization: Related data and functions live together.
  • Maintainability: Changes to one class don't ripple everywhere.
  • Modeling: Natural way to represent real-world entities (BankAccount, Employee, Car).
  • Extensibility: Inheritance and composition let you build on existing code.

Python as Multi-Paradigm

Python supports procedural, functional, and object-oriented programming. In Python, everything is an object — integers, strings, lists, functions, even classes themselves.

# Everything is an object
print(type(42))          # <class 'int'>
print(type("hello"))     # <class 'str'>
print(type([1, 2, 3]))   # <class 'list'>
print(type(print))       # <class 'builtin_function_or_method'>
💡 When to use classes vs functions: Use classes when you need to maintain state across multiple operations or when you have related data and behavior. Use functions for stateless operations and simple transformations.

2. Class Definition and Instantiation

A class is defined with the class keyword. The class body contains attributes and methods.

Basic Class Definition

class Dog:
    """A simple Dog class."""
    pass

# Creating instances
buddy = Dog()
rex = Dog()

print(type(buddy))      # <class '__main__.Dog'>

Class Body and Namespace

The class body creates a namespace (a dictionary). You can inspect it:

class MyClass:

Attribute References

class Circle:

c = Circle()
print(Circle.pi)        # 3.14159 (class access)
print(c.pi)             # 3.14159 (instance access - falls back to class)

Multiple Instances

class Point:

3. The __init__ Constructor

The __init__ method initializes a newly created instance. It's called automatically when you instantiate a class.

Basic __init__

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

alice = Person("Alice", 30)
print(alice.name)       # Alice
print(alice.age)        # 30

Default Parameter Values

class Student:
    def __init__(self, name, grade="A"):
        self.name = name
        self.grade = grade

s1 = Student("Bob")
s2 = Student("Charlie", "B")
print(s1.grade)         # A
print(s2.grade)         # B

The Mutable Default Argument Trap

# BAD: Shared list across all instances!
class Bad:
    def __init__(self, items=[]):
        self.items = items

a = Bad()
b = Bad()
a.items.append(1)
print(b.items)          # [1] — OOPS! b shares a's list

# GOOD: Create new list each time
class Good:
    def __init__(self, items=None):
        self.items = items if items is not None else []

c = Good()
d = Good()
c.items.append(1)
print(d.items)          # [] — Correct! Independent lists
⚠️ Mutable default argument trap: Default values are evaluated once when the function is defined, not each time it's called. Mutable defaults (lists, dicts, sets) are shared across all calls. Always use None as the default and create the mutable object inside the function.

4. The self Parameter

self is the first parameter of instance methods. It represents the instance being operated on.

Why self Is Explicit

class Dog:
    def __init__(self, name):
        self.name = name  # self.name is an instance attribute
    
    def bark(self):       # self is required
        return f"{self.name} says Woof!"

buddy = Dog("Buddy")
print(buddy.bark())      # Buddy says Woof!

How Python Passes self

class Dog:
    def __init__(self, name):
        self.name = name
    
    def bark(self):
        return f"{self.name} says Woof!"

buddy = Dog("Buddy")

# This:
buddy.bark()

# Is equivalent to:
Dog.bark(buddy)          # Python passes buddy as self automatically

self Is Just a Convention

class Dog:
    def __init__(this, name):  # Works, but don't do this!
        this.name = name
    
    def bark(this):
        return f"{this.name} says Woof!"

buddy = Dog("Buddy")
print(buddy.bark())      # Buddy says Woof!
💡 Convention: Always use self for instance methods and cls for class methods. This is the Python community standard and makes code readable.

Accessing Attributes via self

class Counter:
    count = 0  # Class attribute
    
    def __init__(self):
        self.value = 0  # Instance attribute
    
    def increment(self):
        self.value += 1  # Access instance attribute
        Counter.count += 1  # Access class attribute

c1 = Counter()
c2 = Counter()
c1.increment()
c1.increment()
c2.increment()
print(c1.value)          # 2
print(c2.value)          # 1
print(Counter.count)     # 3

5. Instance Attributes vs Class Attributes

Understanding the difference between instance and class attributes is crucial for proper OOP design.

Instance Attributes

  • Unique to each instance
  • Stored in the instance's __dict__
  • Created in __init__ or other methods
  • Accessed via self.attr
class Person:
    def __init__(self, name):
        self.name = name  # Instance attribute

p1 = Person("Alice")
p2 = Person("Bob")
print(p1.__dict__)      # {'name': 'Alice'}
print(p2.__dict__)      # {'name': 'Bob'}

Class Attributes

  • Shared across all instances
  • Stored in the class's __dict__
  • Defined directly in the class body
  • Accessed via ClassName.attr or self.attr
class Dog:
    species = "Canis familiaris"  # Class attribute
    
    def __init__(self, name):
        self.name = name  # Instance attribute

buddy = Dog("Buddy")
rex = Dog("Rex")

print(buddy.species)    # Canis familiaris (from class)
print(rex.species)      # Canis familiaris (from class)
print(Dog.species)      # Canis familiaris

Attribute Lookup Order

Python looks up attributes in this order:

  1. Instance attributes (self.__dict__)
  2. Class attributes (ClassName.__dict__)
  3. Parent class attributes (if inherited)
  4. __getattr__ if defined
class MyClass:
    x = 10  # Class attribute

obj = MyClass()
print(obj.x)            # 10 (from class)

obj.x = 20              # Creates instance attribute
print(obj.x)            # 20 (from instance - shadows class attribute)
print(MyClass.x)        # 10 (class attribute unchanged)

del obj.x               # Remove instance attribute
print(obj.x)            # 10 (falls back to class attribute)

Modifying Class Attributes

class Dog:
    species = "Canis familiaris"
    count = 0
    
    def __init__(self, name):
        self.name = name
        Dog.count += 1  # Modify class attribute

buddy = Dog("Buddy")
rex = Dog("Rex")
print(Dog.count)        # 2

# Modifying class attribute affects all instances
Dog.species = "Canis lupus familiaris"
print(buddy.species)    # Canis lupus familiaris
print(rex.species)      # Canis lupus familiaris

The Mutable Class Attribute Pitfall

# DANGEROUS: Shared mutable state
class Bad:
    items = []  # All instances share this list!
    
    def add(self, item):
        self.items.append(item)  # Modifies the shared list

a = Bad()
b = Bad()
a.add(1)
print(b.items)          # [1] — OOPS! b sees a's change

# SAFE: Create in __init__
class Good:
    def __init__(self):
        self.items = []  # Each instance gets its own list
    
    def add(self, item):
        self.items.append(item)

c = Good()
d = Good()
c.add(1)
print(d.items)          # [] — Correct! Independent lists
⚠️ Mutable class attributes: If a class attribute is mutable (list, dict, set) and you modify it via an instance, you're modifying the shared object. Create mutable attributes in __init__ instead.

6. Instance Methods

Instance methods are functions defined inside a class that operate on instance data.

Definition and Calling

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance
    
    def deposit(self, amount):
        """Add money to the account."""
        if amount > 0:
            self.balance += amount
            return True
        return False
    
    def withdraw(self, amount):
        """Remove money from the account."""
        if 0 < amount <= self.balance:
            self.balance -= amount
            return True
        return False
    
    def get_balance(self):
        """Return current balance."""
        return self.balance

acc = BankAccount("Alice", 1000)
acc.deposit(500)
print(acc.get_balance())  # 1500
acc.withdraw(200)
print(acc.get_balance())  # 1300

Method Chaining

class Builder:
    def __init__(self):
        self.parts = []
    
    def add_part(self, part):
        self.parts.append(part)
        return self  # Enable chaining
    
    def build(self):
        return "-".join(self.parts)

# Method chaining
result = (Builder()
    .add_part("engine")
    .add_part("wheels")
    .add_part("body")
    .build())
print(result)            # engine-wheels-body

The __dict__ Attribute

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

p = Person("Alice", 30)
print(p.__dict__)       # {'name': 'Alice', 'age': 30}

# Add attribute dynamically
p.email = "alice@example.com"
print(p.__dict__)       # {'name': 'Alice', 'age': 30, 'email': 'alice@example.com'}

7. Class Methods (@classmethod)

Class methods receive the class (cls) as the first parameter instead of the instance (self).

Basic Syntax

class MyClass:
    class_attr = "shared"
    
    @classmethod
    def class_method(cls):
        return f"Class: {cls.__name__}, attr: {cls.class_attr}"

# Can be called on class or instance
print(MyClass.class_method())  # Class: MyClass, attr: shared
obj = MyClass()
print(obj.class_method())      # Class: MyClass, attr: shared

Alternative Constructors / Factory Methods

import time
from datetime import datetime

class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day
    
    def __repr__(self):
        return f"Date({self.year}, {self.month}, {self.day})"
    
    @classmethod
    def today(cls):
        """Create Date from today's date."""
        now = datetime.now()
        return cls(now.year, now.month, now.day)
    
    @classmethod
    def from_string(cls, date_str):
        """Create Date from 'YYYY-MM-DD' string."""
        year, month, day = map(int, date_str.split("-"))
        return cls(year, month, day)
    
    @classmethod
    def is_leap_year(cls, year):
        """Check if a year is a leap year."""
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

# Usage
d1 = Date(2024, 1, 15)
d2 = Date.today()
d3 = Date.from_string("2024-12-25")
print(d1)                # Date(2024, 1, 15)
print(d2)                # Date(2025, 7, 19)
print(Date.is_leap_year(2024))  # True

Inheritance Behavior

class Animal:
    def __init__(self, name):
        self.name = name
    
    @classmethod
    def create(cls, name):
        return cls(name)  # cls refers to the actual class

class Dog(Animal):
    def speak(self):
        return f"{self.name} says Woof!"

class Cat(Animal):
    def speak(self):
        return f"{self.name} says Meow!"

# cls refers to the subclass
dog = Dog.create("Rex")
cat = Cat.create("Whiskers")
print(dog.speak())       # Rex says Woof!
print(cat.speak())       # Whiskers says Meow!

8. Static Methods (@staticmethod)

Static methods are regular functions that live inside a class's namespace. They don't receive self or cls.

Basic Syntax

class MathUtils:
    @staticmethod
    def is_even(n):
        return n % 2 == 0
    
    @staticmethod
    def factorial(n):
        if n < 0:
            raise ValueError("Negative numbers not allowed")
        result = 1
        for i in range(2, n + 1):
            result *= i
        return result

# Can be called on class or instance
print(MathUtils.is_even(4))    # True
print(MathUtils.factorial(5))  # 120

obj = MathUtils()
print(obj.is_even(7))          # False

When to Use Static Methods

class EmailValidator:
    @staticmethod
    def is_valid(email):
        """Validate email format."""
        return "@" in email and "." in email.split("@")[-1]
    
    @staticmethod
    def get_domain(email):
        """Extract domain from email."""
        return email.split("@")[-1]

# Usage
print(EmailValidator.is_valid("user@example.com"))  # True
print(EmailValidator.get_domain("user@example.com"))  # example.com

9. String Representations: __str__ vs __repr__

Python uses special methods to convert objects to strings. Having good representations is essential for debugging and user output.

The Problem

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(p)                # <__main__.Point object at 0x...> — Not helpful!

__repr__: Developer-Friendly

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"

p = Point(1, 2)
print(repr(p))          # Point(x=1, y=2)
# In interactive mode, this is what you see

__str__: Human-Readable

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def __str__(self):
        return f"({self.x}, {self.y})"
    
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"

p = Point(1, 2)
print(p)                # (1, 2) — uses __str__
print(f"{p}")           # (1, 2) — uses __str__
print(f"{p!r}")         # Point(x=1, y=2) — uses __repr__

Fallback Behavior

class OnlyRepr:
    def __init__(self, value):
        self.value = value
    
    def __repr__(self):
        return f"OnlyRepr({self.value})"

obj = OnlyRepr(42)
print(str(obj))         # OnlyRepr(42) — falls back to __repr__
print(repr(obj))        # OnlyRepr(42)

When Each Is Used

ContextMethod Used
print(obj)__str__

f"{obj}"__str__

Interactive display__repr__

💡 Best practice: Always define __repr__. It's used in debugging, logging, and interactive mode. __str__ is optional but nice to have for user-facing output.

10. Public, Private, and Name Mangling

Python uses naming conventions to indicate attribute visibility, not access modifiers like other languages.

Public Attributes (No Prefix)

class Public:
    def __init__(self, name):
        self.name = name  # Public attribute

obj = Public("Alice")
print(obj.name)         # Alice — accessible anywhere

Protected Convention: _attr

class Protected:
    def __init__(self, name):
        self._name = name  # Protected (convention only)
    
    def get_name(self):
        return self._name

obj = Protected("Bob")
print(obj._name)        # Bob — works, but signals "internal use"
print(obj.get_name())   # Bob — preferred access

Name Mangling: __attr

class Base:
    def __init__(self):
        self.__private = 1  # Name mangled to _Base__private

class Derived(Base):
    def __init__(self):
        super().__init__()
        self.__private = 2  # Name mangled to _Derived__private

base = Base()
derived = Derived()

# print(base.__private)  # AttributeError!
print(base._Base__private)  # 1 — Access mangled name
print(derived._Derived__private)  # 2

Why Name Mangling Exists

class Mapping:
    def __init__(self, iterable):
        self.items_list = []
        self.__update(iterable)
    
    def update(self, iterable):
        for item in iterable:
            self.items_list.append(item)
    
    __update = update  # Private copy of update

class MappingSubclass(Mapping):
    def update(self, keys, values):
        # This doesn't conflict with Mapping's __update
        for item in zip(keys, values):
            self.items_list.append(item)

Name Mangling Is NOT Access Control

class Secret:
    def __init__(self):
        self.__password = "secret123"

obj = Secret()
# obj.__password  # AttributeError
print(obj._Secret__password)  # secret123 — Anyone can access!
⚠️ Name mangling is not security: It's designed to prevent accidental name collisions in inheritance, not to hide data. Anyone can access mangled names by prefixing with _ClassName.

11. The @property Decorator

Properties provide a way to define methods that are accessed like attributes. They allow validation, computation, and controlled access.

Getter: @property

class Circle:
    def __init__(self, radius):
        self._radius = radius
    
    @property
    def radius(self):
        """Get the radius."""
        return self._radius

c = Circle(5)
print(c.radius)         # 5 — Looks like attribute access

Setter: @name.setter

class Circle:
    def __init__(self, radius):
        self._radius = radius
    
    @property
    def radius(self):
        return self._radius
    
    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError("Radius cannot be negative")
        self._radius = value

c = Circle(5)
c.radius = 10           # Works
# c.radius = -1         # ValueError: Radius cannot be negative

Deleter: @name.deleter

class Circle:
    def __init__(self, radius):
        self._radius = radius
    
    @property
    def radius(self):
        return self._radius
    
    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError("Radius cannot be negative")
        self._radius = value
    
    @radius.deleter
    def radius(self):
        del self._radius

c = Circle(5)
del c.radius            # Deletes _radius

Read-Only Properties

class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius
    
    @property
    def celsius(self):
        return self._celsius
    
    @property
    def fahrenheit(self):
        """Read-only computed property."""
        return self._celsius * 9/5 + 32

t = Temperature(100)
print(t.fahrenheit)     # 212.0
# t.fahrenheit = 100    # AttributeError: can't set attribute

Validation in Setters

class Student:
    def __init__(self, name, grade):
        self.name = name
        self.grade = grade  # Uses setter
    
    @property
    def grade(self):
        return self._grade
    
    @grade.setter
    def grade(self, value):
        if value not in "ABCDF":
            raise ValueError(f"Invalid grade: {value}")
        self._grade = value

s = Student("Alice", "A")
s.grade = "B"           # Works
# s.grade = "X"         # ValueError: Invalid grade: X

Properties vs Getters/Setters

# Java-style (verbose)
class JavaStyle:
    def get_name(self):
        return self._name
    
    def set_name(self, value):
        self._name = value

# Python-style (clean)
class PythonStyle:
    @property
    def name(self):
        return self._name
    
    @name.setter
    def name(self, value):
        self._name = value

# Usage
obj = PythonStyle()
obj.name = "Alice"      # Clean attribute syntax
print(obj.name)         # Clean access

Property Inheritance

class Base:
    def __init__(self, value):
        self._value = value
    
    @property
    def value(self):
        return self._value

class Derived(Base):
    @property
    def value(self):
        """Override with additional logic."""
        return f"Derived: {super().value}"

obj = Derived(42)
print(obj.value)        # Derived: 42

Caching with Properties

from functools import cached_property

class DataAnalyzer:
    def __init__(self, data):
        self.data = data
    
    @cached_property
    def expensive_computation(self):
        """Compute once, cache forever."""
        print("Computing...")
        return sum(x ** 2 for x in self.data)

analyzer = DataAnalyzer(range(1000))
print(analyzer.expensive_computation)  # Computes...
print(analyzer.expensive_computation)  # Returns cached value

12. Advanced Topics

12a. __slots__ for Memory Optimization

__slots__ restricts attribute creation and eliminates the per-instance dictionary, saving memory.

Basic Syntax

class Point:
    __slots__ = ('x', 'y')
    
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(p.x, p.y)        # 1 2
# p.z = 3              # AttributeError: 'Point' object has no attribute 'z'

Memory Savings

import sys

class RegularPoint:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class SlottedPoint:
    __slots__ = ('x', 'y')
    
    def __init__(self, x, y):
        self.x = x
        self.y = y

regular = RegularPoint(1, 2)
slotted = SlottedPoint(1, 2)

print(sys.getsizeof(regular))       # 48 bytes (approx)
print(sys.getsizeof(regular.__dict__))  # 64 bytes (approx)
print(sys.getsizeof(slotted))      # 40 bytes (approx)
# SlottedPoint has no __dict__!

Limitations

class Point:
    __slots__ = ('x', 'y')
    
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
# p.z = 3              # AttributeError: 'Point' object has no attribute 'z'
# print(p.__dict__)    # AttributeError: 'Point' object has no attribute '__dict__'

__slots__ with Inheritance

class Base:
    __slots__ = ('a',)

class Derived(Base):
    __slots__ = ('b',)

obj = Derived()
obj.a = 1               # From Base
obj.b = 2               # From Derived
print(obj.a, obj.b)     # 1 2
💡 When to use __slots__: Use when you have many instances of the same class and memory is critical. Trade-off: less flexibility (no dynamic attributes) for memory savings.

12b. Dataclasses

Dataclasses reduce boilerplate for classes that primarily store data.

Basic Syntax

from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)
print(p)                # Point(x=1.0, y=2.0) — auto __repr__
print(p.x, p.y)        # 1.0 2.0

Auto-Generated Methods

from dataclasses import dataclass

@dataclass
class Student:
    name: str
    grade: str
    gpa: float

# Auto-generated __init__
s1 = Student("Alice", "A", 3.9)

# Auto-generated __repr__
print(s1)                # Student(name='Alice', grade='A', gpa=3.9)

# Auto-generated __eq__
s2 = Student("Alice", "A", 3.9)
print(s1 == s2)          # True — value equality

Field Customization

from dataclasses import dataclass, field

@dataclass
class Student:
    name: str
    grades: list = field(default_factory=list)
    gpa: float = 0.0

s1 = Student("Alice")
s2 = Student("Bob", [3.5, 4.0])
print(s1.grades)        # []
print(s2.grades)        # [3.5, 4.0]

When to Use Dataclasses

  • Data containers (records, configs)
  • Classes with mostly data, little behavior
  • When you need __init__, __repr__, __eq__
  • Replace simple namedtuple usage

12c. Descriptor Protocol

Descriptors are objects that define __get__, __set__, or __delete__ methods. They control attribute access.

Basic Descriptor

class Validated:
    def __set_name__(self, owner, name):
        self.public_name = name
        self.private_name = '_' + name
    
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.private_name, None)
    
    def __set__(self, obj, value):
        self._validate(value)
        setattr(obj, self.private_name, value)
    
    def _validate(self, value):
        pass  # Override in subclass

class PositiveNumber(Validated):
    def _validate(self, value):
        if not isinstance(value, (int, float)) or value <= 0:
            raise ValueError(f"{self.public_name} must be positive")

class Temperature:
    celsius = PositiveNumber()
    
    def __init__(self, celsius):
        self.celsius = celsius

t = Temperature(100)
print(t.celsius)        # 100
# t.celsius = -10       # ValueError: celsius must be positive

Data Descriptors vs Non-Data Descriptors

TypeDefinesPriority
Data descriptor__set__ (and __get__)Higher than instance dict
Non-data descriptorOnly __get__Lower than instance dict
 
class DataDescriptor:
    def __get__(self, obj, objtype=None):
        return "data descriptor"
    
    def __set__(self, obj, value):
        pass

class NonDataDescriptor:
    def __get__(self, obj, objtype=None):
        return "non-data descriptor"

class MyClass:
    data = DataDescriptor()
    non_data = NonDataDescriptor()

obj = MyClass()
obj.non_data = "instance value"  # Overrides non-data descriptor
print(obj.non_data)        # instance value
print(obj.data)            # data descriptor (can't override)

13. Practical Examples

Complete BankAccount Class

class BankAccount:
    """A complete bank account implementation."""
    
    _account_count = 0
    
    def __init__(self, owner, balance=0.0):
        self._owner = owner
        self._balance = balance
        self._transactions = []
        BankAccount._account_count += 1
        self._account_number = f"ACC{BankAccount._account_count:06d}"
    
    @property
    def owner(self):
        return self._owner
    
    @property
    def balance(self):
        return self._balance
    
    @property
    def account_number(self):
        return self._account_number
    
    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit amount must be positive")
        self._balance += amount
        self._transactions.append(("DEPOSIT", amount))
        return self
    
    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Withdrawal amount must be positive")
        if amount > self._balance:
            raise ValueError("Insufficient funds")
        self._balance -= amount
        self._transactions.append(("WITHDRAWAL", amount))
        return self
    
    def transfer(self, other, amount):
        self.withdraw(amount)
        other.deposit(amount)
        self._transactions.append(("TRANSFER", -amount, other.account_number))
        return self
    
    @classmethod
    def from_dict(cls, data):
        """Create account from dictionary."""
        return cls(data['owner'], data.get('balance', 0))
    
    @staticmethod
    def validate_amount(amount):
        """Validate that amount is a positive number."""
        return isinstance(amount, (int, float)) and amount > 0
    
    def __repr__(self):
        return f"BankAccount(owner='{self._owner}', balance={self._balance:.2f})"
    
    def __str__(self):
        return f"{self._owner}'s account ({self._account_number}): ${self._balance:.2f}"
    
    def __len__(self):
        return len(self._transactions)

# Usage
acc1 = BankAccount("Alice", 1000)
acc2 = BankAccount.from_dict({"owner": "Bob", "balance": 500})
acc1.deposit(200).withdraw(100).transfer(acc2, 50)
print(acc1)             # Alice's account (ACC000001): $1050.00
print(acc2)             # Bob's account (ACC000002): $550.00
print(len(acc1))        # 3 transactions

Complete Vector Class

import math

class Vector:
    """A 2D vector class with mathematical operations."""
    
    __slots__ = ('x', 'y')
    
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    @property
    def magnitude(self):
        """Return the magnitude (length) of the vector."""
        return math.sqrt(self.x ** 2 + self.y ** 2)
    
    @property
    def normalized(self):
        """Return a unit vector in the same direction."""
        mag = self.magnitude
        if mag == 0:
            return Vector(0, 0)
        return Vector(self.x / mag, self.y / mag)
    
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)
    
    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)
    
    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)
    
    def __rmul__(self, scalar):
        return self.__mul__(scalar)
    
    def __abs__(self):
        return self.magnitude
    
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
    
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"
    
    def __str__(self):
        return f"({self.x}, {self.y})"
    
    def dot(self, other):
        """Return dot product of two vectors."""
        return self.x * other.x + self.y * other.y
    
    def cross(self, other):
        """Return cross product (z-component) of two vectors."""
        return self.x * other.y - self.y * other.x

# Usage
v1 = Vector(3, 4)
v2 = Vector(1, 2)
print(v1 + v2)         # (4, 6)
print(v1 - v2)         # (2, 2)
print(v1 * 2)          # (6, 8)
print(3 * v1)          # (9, 12)
print(abs(v1))         # 5.0
print(v1.magnitude)    # 5.0
print(v1.normalized)   # (0.6, 0.8)
print(v1.dot(v2))      # 11
print(v1.cross(v2))    # 2
